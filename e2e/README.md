# Интеграционные (e2e) тесты

Этот каталог содержит end-to-end тесты, написанные на [Playwright](https://playwright.dev/). Тесты запускают реальный браузер и проходят ключевые пользовательские сценарии через фронтенд и бэкенд.

## Зафиксированные сценарии

### S1 — Гость бронирует встречу

1. Гость открывает главную страницу `/` и видит список типов событий.
2. Выбирает тип события «Консультация» и нажимает «Забронировать».
3. На странице `/event-types/:id/book` выбирает первый доступный слот.
4. Заполняет форму (имя и email) и отправляет бронь.
5. Попадает на страницу `/bookings/:id/confirmation` с текстом «Бронирование подтверждено» и деталями встречи.

### S2 — Владелец видит и отменяет бронь

1. После успешного бронирования владелец открывает `/admin/bookings`.
2. В таблице отображается созданная бронь с именем гостя, типом события и временем.
3. Владелец нажимает «Отменить» напротив брони.
4. Бронь исчезает из таблицы, отображается сообщение «Нет предстоящих бронирований».

## Запуск тестов

```bash
# Установить зависимости и браузер (один раз)
cd e2e
npm install
npx playwright install chromium

# Из корня проекта
npm run test:e2e

# С открытым браузером
npm run test:e2e:headed

# UI-режим для отладки
npm run test:e2e:ui
```

## Архитектура

- `playwright.config.ts` — настройки Playwright, запуск двух `webServer` (backend на `:8010`, frontend на `:5273`).
- `lib/paths.ts` — пути проекта.
- `lib/start-backend.mjs` — перед стартом сервера создаёт чистую тестовую БД, прогоняет миграции и запускает `E2eSeeder`.
- `tests/booking.spec.ts` — покрывает S1 и S2 в одном сквозном тесте.

## Примечания

- Тесты используют `timezoneId: 'Europe/Moscow'` и `locale: 'ru-RU'`, чтобы даты/время совпадали с русским UI и генератором слотов.
- Подбор первого доступного слота защищён от ситуации, когда на текущую дату нет свободных окон (поздний вечер): при необходимости тест листает календарь вперёд до первого слота.
